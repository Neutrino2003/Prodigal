# Prodigal Payment Agent Codebase Review

This repository contains a Python payment-support conversation agent in `payment-agent/`. The agent uses a deterministic state machine for the payment flow and LLM calls only for extracting structured fields from user text and refining responses.

## Current Quality Assessment

Overall, the core design is good for an assignment-sized codebase. The strongest part is the separation between conversation orchestration, validation, verification, API access, and LLM adapters. This makes the payment flow easier to test than a fully LLM-driven agent.

The code is readable, but not production-ready yet. The main gaps are small test coverage, generated cache files in the working tree, a few stale comments/docs, and limited error recovery for multi-turn user input.

## What Is Good

- `payment_agent/agent.py` keeps the payment flow deterministic with explicit phases.
- `payment_agent/domain/validators.py` and `payment_agent/domain/verification.py` are pure Python, which keeps business rules testable.
- `payment_agent/services/tools.py` validates account/payment API payloads with Pydantic models.
- Sensitive card number and CVV are cleared after payment attempts.
- Tests pass locally with `python -m pytest -q`.
- LLM calls degrade to template/fallback behavior if the API key or package is unavailable.

## Main Issues

- The repository currently has generated files: `__pycache__/` and `.pytest_cache/`. These should not be committed.
- `payment-agent/conftest.py` only contains a docstring and does not configure pytest. It can be removed unless fixtures are added later.
- `payment-agent/tests/__init__.py` is probably unnecessary unless you intentionally want `tests` to be a package.
- The existing docs were partly stale: the old README described some paths that do not match the actual package layout.
- `ConversationState.name_matched` is unused and can be deleted unless partial-verification state is planned.
- Internal phases now auto-resolve inside `Agent.next()`, so lookup, verification, balance disclosure, and payment processing do not require blank user turns.
- Tests focus on happy paths and basic validation. More tests are needed for network failures, payment API failures, retries, invalid card retries, and terminal states.

## Files That Should Be Deleted

- `payment-agent/**/__pycache__/`: Python bytecode cache generated by running Python. It is environment-specific and should never be versioned.
- `payment-agent/.pytest_cache/`: pytest runtime cache. It speeds up local test runs but should not be part of source control.
- `.codex`: currently an empty local artifact at the repository root. It has no project value.
- `payment-agent/conftest.py`: delete if it remains only a docstring. Keep it only if pytest fixtures or path setup are added.
- `payment-agent/tests/__init__.py`: delete if tests do not need package-relative imports. Pytest can discover tests without it.

## Files To Keep

- `Agent_Engineer_-_payment_agent_assignment.pdf`: keep if it is the assignment/source brief. Delete only if the repository should contain source code only.
- `payment-agent/DESIGN.md`: keep because it explains architectural decisions. Keep it aligned with the actual provider/model configuration.
- Empty package files like `payment_agent/domain/__init__.py`, `payment_agent/llm/__init__.py`, and `payment_agent/services/__init__.py`: keep them because they mark package boundaries and support imports.

## Project Structure And File Guide

### Repository Root

| File or folder | Purpose |
|---|---|
| `README.md` | This codebase review and file guide. |
| `.gitignore` | Prevents Python caches, local env files, editor files, and generated eval results from being tracked. |
| `.codex` | Empty local artifact. Safe to delete. |
| `Agent_Engineer_-_payment_agent_assignment.pdf` | Assignment brief or reference document. Keep only if useful to reviewers. |
| `payment-agent/` | Main Python project. |

### `payment-agent/`

| File | Purpose |
|---|---|
| `.env.example` | Template for local environment variables such as `NVIDIA_API_KEY`, `NVIDIA_BASE_URL`, `PAYMENT_API_BASE_URL`, and timeouts. |
| `README.md` | Detailed usage guide for the payment agent project. |
| `DESIGN.md` | Architecture notes, decisions, accepted tradeoffs, and future improvements. |
| `requirements.txt` | Runtime and test dependencies. |
| `cli.py` | Interactive terminal demo using Rich. Creates an `Agent`, reads user input, prints responses, and shows final state. |
| `conftest.py` | Pytest configuration placeholder. Currently contains no functional configuration. |

### `payment-agent/payment_agent/`

| File | Purpose |
|---|---|
| `__init__.py` | Public package exports: `Agent`, `AccountData`, `ConversationState`, and `Phase`. |
| `agent.py` | Main state-machine orchestrator. Handles phase transitions, calls extraction, validation, account lookup, verification, and payment processing. |
| `config.py` | Loads `.env` values and exposes immutable `settings`. Handles integer env parsing with safe defaults. |
| `prompts.py` | Central location for extraction prompts, response templates, and fallback messages by phase. |
| `state.py` | Defines the `Phase` enum, private `AccountData` model, and mutable `ConversationState` dataclass. |

### `payment-agent/payment_agent/domain/`

| File | Purpose |
|---|---|
| `__init__.py` | Package marker for domain logic. |
| `validators.py` | Pure validation functions for account IDs, dates, card type, Luhn checks, CVV, expiry, and payment amount. |
| `verification.py` | Strict identity verification against account data using exact comparisons for name and one verification factor. |

### `payment-agent/payment_agent/llm/`

| File | Purpose |
|---|---|
| `__init__.py` | Package marker for LLM adapters. |
| `extractor.py` | Converts user messages into structured dictionaries using NVIDIA NIM if configured, with rule-based fallback extraction. |
| `responder.py` | Formats template responses and optionally asks NVIDIA NIM to refine the wording. |

### `payment-agent/payment_agent/services/`

| File | Purpose |
|---|---|
| `__init__.py` | Package marker for service integrations. |
| `tools.py` | HTTP wrappers for account lookup and payment processing. Also defines result dataclasses and Pydantic request models. |

### `payment-agent/eval/`

| File | Purpose |
|---|---|
| `__init__.py` | Package marker for evaluation helpers. |
| `runner.py` | Runs scripted conversations through the agent, scores them, and saves JSON results. |
| `personas.py` | Defines test personas and scripted conversation variants. |
| `judge.py` | Scores conversations with an LLM when available, with a fallback heuristic score. |
| `metrics.py` | Loads the latest eval result and prints a summary report. |
| `results/` | Generated evaluation output directory. Should stay untracked. |

### `payment-agent/tests/`

| File | Purpose |
|---|---|
| `__init__.py` | Optional package marker for tests. Usually not required by pytest. |
| `test_basic.py` | Unit tests for imports, validators, state defaults, verification, and agent initialization. |
| `test_integration.py` | Integration-style tests for the state machine and sensitive card-data clearing. |

## How To Run

```bash
cd payment-agent
pip install -r requirements.txt
cp .env.example .env
python cli.py
```

Run tests:

```bash
cd payment-agent
python -m pytest -q
```

Run scripted evaluation:

```bash
cd payment-agent
python -m eval.runner
python -m eval.metrics
```

2. Delete `.codex` if no local tool needs it.
3. Remove `payment-agent/conftest.py` unless it gets real pytest configuration.
4. Remove `payment-agent/tests/__init__.py` if tests continue to run without it.
